# 性能优化

把一句宽泛的"让它更快"变成**可复现的用户路径测量**与**小的、有证据的修复**。

**这是指导，不是配额也不是脚本：广泛普查、跟随实测成本，并拒绝那些看起来诱人、但没有改善用户真正运行的工作负载的改动。**

**REQUIRED：** 进程、时钟、浏览器测试与异步拆除用 `ssid-test-reliability`；推送前选证据用 `ssid-pre-push-checks`。同批安装。

## 定范围与当前权威

**先"同意"这几件事**：用户可见的端点、工作负载范围、资源约束、可接受的微小行为差异、以及**停止规则**。**停止规则是防止性能工作无限蔓延的唯一闸门。**

**四层测量必须分开**——跨层推断与"快的历史迭代器证明传输快"是同一类错误：

| 层 | 形态 |
|---|---|
| 主进程 | `shell/main.mjs` |
| 内核 | `kernel.bundle.mjs` + DSH |
| 渲染进程 | Web 界面 |
| 磁盘与归档 | profile、`dsh-runtime.tar.gz` |

**启动时间必须定义终点**：可观察点有进程起、splash 出现、splash 消失、首屏可交互、归档部署完成。**不定终点就没法比较。**

**测量本地开销时排除模型与网络延迟，并陈述这个排除**——不要把结果称为完整的产品延迟。

**以仓库 HEAD 为准，不以本地 dev 进程为准**——dev 热更新会让本地状态偏离 HEAD。

## 普查用户路径，再排序候选

广度有帮助时委派独立域；**要求测量与生产调用点，而不是猜测**。**不要让第一个好候选中止普查。**

| # | 域 |
|---:|---|
| 1 | **冷启动与热启动**：进程起 → splash → 归档部署（首启/升级）→ 首屏可交互 |
| 2 | **大会话**：多回合历史、工具密集、单条大结果、会话列表与切换、导航条与面板 |
| 3 | **渲染与交互**：首次绘制、滚动、面板展开折叠、侧栏切换、隐藏视图激活 |
| 4 | **归档与部署**：`prepare-runtime.mjs` 耗时、归档解压与校验、vendor 同步 |

**独立成本驱动因素要分别变动**——字节、事件数、回合数、工具数、DOM 节点数是**不同的量**。**不要把一个"大量微小相同消息"的负载称为现实负载，除非检查过它压的是哪个用户操作。** 包含典型与尾部负载，但**避免没有决策价值的组合矩阵**。

按**观察到的用户延迟、CPU/分配、保留内存、发生频率、置信度**排序。每条候选必须点名：**生产消费者、重复工作、预期复杂度、最小的可证伪干预、必须保持稳定的行为**。

**可疑的循环、未使用的缓存、或大文件本身不是瓶颈的证据。**

## 先建可复现的测量

**若用户授权检查本地语料，只提取聚合的工作负载特征。绝不把提示词、输出、路径、身份、ID、凭据、录制或可识别片段复制进 fixture、日志、截图或产物。**

> **本仓库的用户数据比一般仓库更敏感**——会话日志里就是真实对话内容。聚合时**只取计数与长度分布**。

用经复核的常量生成固定输入；**没有任何基准依赖用户的主目录、环境仓库、网络服务或私有数据。**

**动笔前先记录一张测量卡**：

| 字段 | 必须给出的决定 |
|---|---|
| 用户操作 | 确切动作与**外部可观察的完成条件** |
| 工作负载 | 固定维度、分布、构造种子/常量，以及**为什么它压到普通与尾部使用** |
| 入口路径 | 生产调用/组合与构建产物；被 mock 的外部边界 |
| 时钟 | 纳入的 setup、冷/热状态、计时起止、**被排除的成本** |
| 内存 | 可达的端点对象、基线、GC 策略、保留 vs 瞬时上限 |
| 裁决 | 原始样本、选定的聚合、校准的绝对值/比例/内存上限、**负向控制** |
| 行为 | 属主功能测试，以及**被允许的微小差异** |

**用全新子进程与私有临时根**做冷启动与进程内存样本；热样本显式保留既定缓存；**绝不让 fixture 的 setup 悄悄预热一个冷场景**；两侧保持相同输入、校验、完成条件与可达输出。**解析后丢弃的基线不能与经过校验的保留结果相比。**

**本仓库没有可扩展的测量 lane**——先建**一条最小的**（一个脚本 + 一个输出格式），再开始优化。**不要为每次优化各造一套脚本。**

**不要为了让某次运行好看而放宽预算或挑一次走运的运行。**

## 证明回归，再移除工作

**改生产代码之前**先跑未优化的负载，保存命令、版本、运行时/平台、fixture 维度、原始测量与裁决。

把失败场景**缩减到仍然压到真实瓶颈**，然后**在动手前给可证伪假设排序**；用 profile、分配样本、工作计数或阶段计时来区分它们。

**值得测的模式**（不是自动处方）：

1. 让紧凑表示**一路保持紧凑**；消费者需要已定内容或一个聚合时，避免逐 delta 对象。
2. **只有在识别出真正的归属与信任转移之后**才移除重复的解析、拷贝、冻结与校验。**同进程类型化借用不是削弱持久或 wire 解析的许可。**
3. 流式转换产物并**约束中间状态**，而不是保留每一代；在用户操作需要处**包含发布、校验与可写就绪义务**。
4. **分离只读准备与写入/发布工作**，但**不要把被 await 的工作挪到一个正确性所要求的端点之后**。
5. 延迟非活跃视图与折叠细节的工作；**同时测量首次激活与保留状态**。**延迟不是删除，视口高亮不是完整虚拟化。**
6. **稳定标识、收窄订阅**，使一个变更节点不会让整段历史失效；**保持更新顺序与即时事件行为**。
7. 用合适的数据结构替代反复移位/扫描/重建；**测量整个消费者路径**而不只是孤立的容器操作。**revision-keyed 复用或 singleflight 只在有显式失效、有界保留、独立等待者取消与拆除归属时才用。**

**一次只改一个因果因素**；重跑聚焦场景**与其端到端父场景**。

**负向控制的定义**：**一个宽到让回归通过的阈值不是保护；低于已验证噪声底的预算也不可靠。**

## 保持行为与资源归属

**性能测量补充功能证据，不替代它。** 跑或补最窄的属主测试（输出、排序、分页、错误、取消、并发、拆除）。

保持**会话日志的等价性**（与 DSH 的会话格式契约）、已发布代的不可变性、原子发布、必需校验与可写就绪。

**不要为了达到一个数字而静默截断历史、跳过工具结果、禁用不变量或改变生命周期语义。**

**拒绝一次优化，当**：端到端增益消失 / 典型负载实质性回退 / **复杂度超过小收益** / 取消·保留·持久性**无法解释与测试**。**简短记录被否证的假设，而不是扩大范围来为它辩护。**

## 交付一个有限的、可评审的结果

持久理由写进 `docs/决策/`；**检查相关记录是否被取代，但不要把性能工作变成全库行文清理**。**可复用流程留在这里，场景相关的真相留在它的基准或包属主处。**

应用 `ssid-pre-push-checks`，**只报告执行过的证据**，并查看 CI 而不是假设本地计时能证明 runner 稳定性——**本仓库的 CI 不跑测试，所以"本地计时"就是全部证据：这抬高了重复测量的必要性**。

标记完成之后，用代码与可执行证据评估评审意见；**不要仅仅因为一份报告来自机器人就驳回它**。

**结果摘要格式**：

> 工作负载 → 前后绝对值与比例 → 端点与内存语义 → 行为证据 → 负向控制 → 确切检查 → 排除项

**区分作者报告的历史数字、新的本地测量与 CI 证据。** **停在约定的场景与修复范围内，保留一份简短的排序后续清单，而不是追逐无关机会。**
