## 与上游的差异

**保留**（判据一字未减）：

- **测量卡 7 字段**（用户操作 / 工作负载 / 入口路径 / 时钟 / 内存 / 裁决 / 行为）——这是本 skill 最有价值的产出：有了它，"更快"才是一个可证伪的命题。
- **7 条优化模式的"值得测"清单**，含「只比较**能独立分叉**的观测才算有用」式的表述（同进程类型化借用不是削弱持久或 wire 解析的许可）。
- **隐私纪律**整段。
- **测量诚实性**：全新子进程与私有临时根、热样本显式保留缓存、**绝不让 fixture 的 setup 悄悄预热冷场景**、**解析后丢弃的基线不能与经过校验的保留结果相比**。
- **负向控制的定义**：一个宽到让回归通过的阈值不是保护；低于已验证噪声底的预算也不可靠。
- **四种拒绝优化的情形**与「简短记录被否证的假设，而不是扩大范围来为它辩护」。
- 结果摘要格式七段式。

**改写**：

- 引用换成本地（手册、`ssid-test-reliability`、`ssid-pre-push-checks`、`docs/决策/`）。
- **端点是四层而不是两层**：主进程 / 内核 / 渲染进程 / 磁盘与归档。跨层推断（"主进程快了所以界面快了"）与上游禁止的"Node 折叠证明浏览器响应"是同一类错误。
- **启动时间必须定义终点**（进程起 / splash 出现 / splash 消失 / 首屏可交互 / 归档部署完成）——不定终点就没法比较。
- 4 个普查域换成本地域（冷热启动 / 大会话 / 渲染与交互 / 归档与部署）。
- **删掉测量基建的整段依赖**（Node 机器乘数、浏览器 CI 校准、共享时间校准、预算作为源码常量），改为：**先建一条最小的测量 lane（一个脚本 + 一个输出格式），再开始优化**；并明确警告不要为每次优化各造一套脚本。
- `Deliver a bounded, reviewable result`：删除 stacked PR / 官方 GitHub stacks / 独立 worktree 整段，保留其中通用的「在编辑前选好分层；每一层都要可合并」。
- 「查看 CI 而不是假设本地计时能证明 runner 稳定性」加一句：**本仓库的 CI 不跑测试，所以"本地计时"就是全部证据——这抬高了重复测量的必要性**。

**新增**：

- **隐私纪律提权**：本仓库的用户数据比一般仓库更敏感（会话日志里就是真实对话内容），聚合时只取计数与长度分布。
- **以仓库 HEAD 为准，不以本地 dev 进程为准**（dev 热更新会让本地状态偏离 HEAD）。

**删除**：0 个部件。删掉的是上游引用的测量基建（本仓库不存在），判据本体未动。
