# SSiD 测试可靠性

让测试的失败**指向被测行为**，而不是指向调度、残留状态、平台差异或不足的预算。这是判据，不是脚本。

**REQUIRED BACKGROUND：**
- `ssid-prose-standard` 拥有本文引用的**完整命题规则**——增删测试注释时用。
- `ssid-pre-push-checks` 管**什么时候必须跑哪些检查**；本 skill 管**测试怎么写才可靠**。
- 三者同批安装。分开装会让引用指向不存在的判据。

## 1. 先读归属规则

动手前确认这套测试**实际用什么配置跑**：

| 运行器 | 归属规则在哪 |
|---|---|
| vitest（10 个插件） | 各插件的 `vitest.config.ts`——只设 `include` 与 `environment`，**没有超时配置** |
| node:test（shell 本体、dsh-chat-rail、dsh-quick-toolbar、dsh-ssid-panels） | **没有配置文件**——纪律只存在于 `package.json` 的 `test` 脚本里 |
| Playwright | `shell/tests/plugin-adapt/playwright.config.ts` |

外加 `docs/SSiD开发手册.md` §9（插件开发与测试规范，含 L1/L2/L3 分级门槛）。

**不要假设"有测试就有纪律"**：`plugins/dsh-ssid-panels/tests/` 下有两个测试文件，但那个包**没有 `test` 脚本**、也没装 vitest，唯一入口是 `ssid-release` skill 里的手跑命令——而且**必须在仓库根跑**，否则 `ERR_MODULE_NOT_FOUND`。CI 不会跑它们。

## 2. 建模执行拓扑

测试可能同时运行在四层，**每层的隔离边界不同**：

| 层 | 形态 |
|---|---|
| 1 | 同一 spec 文件内的用例 |
| 2 | 并行的 spec 文件 / worker 进程 |
| 3 | 多个包的测试同时跑 |
| 4 | 本地开发机 vs GitHub runner |

**进程隔离不隔离主机的端口、可预测文件系统路径、外部服务、数据库、socket 或继承的子进程。**

**不要因为一个 fixture 缺隔离就把整个套件串行化**——顺序化一个块无法保护主机资源免受另一个文件、进程或 runner 的干扰。

## 3. 原子分配资源

- **用资源所有者的分配器**，不要"先检查可用、稍后再占"：网络用 `listen(0)`，**在服务器报告 listening 之后**才读回地址；**绝不扫描空闲端口然后稍后绑定**。
- 用 `mkdtemp` 建私有临时根；**不要获取可预测的共享路径**。
- 给共享数据库、socket、会话、输出位置**唯一的按用例命名空间**。
- 需要"路径必须尚不存在"时用**独占创建**。
- **稳定的录制标识符要与临时传输地址分开。**
- **仅作为解析器输入或期望值出现的字面路径/URL 不是被获取的资源**——不要因为看起来固定就改写它们。

**本仓库的现存问题**：`shell/tests/plugin-adapt/` 下约 28 个探针脚本硬编码 `'http://127.0.0.1:9222'`（未走 `SSID_CDP` 回退），另有 5 个写死 `3083` / `54170`，2 个写死用户绝对路径。**该目录的 `README.md` 自己已写明"页面 URL 是随机端口，断言勿硬编码端口"。** 规范写法在同一目录里就有——约 22 个文件用 `process.env.SSID_CDP ?? 'http://127.0.0.1:9222'`。**新增脚本一律用环境变量回退；改到旧脚本时顺手统一。**

## 4. 隔离进程全局状态

把 `process.env`、`cwd`、假计时器、locale 与时区、模块 mock、注册表、console 钩子、`globalThis`、全局 `fetch` 拦截**都当独占可变资源**。

手法固定：**捕获原值是缺失还是存在 → 恢复那个确切状态 → 立即注册恢复 → 最小作用域 `try/finally` → 保留 `afterEach` 兜底 → 拦截最窄的确切请求**。

两个运行器**都是显式导入**（没有开 `globals: true`），所以写法几乎一致：

```js
// vitest
import { describe, it, expect, beforeEach, afterEach, vi } from 'vitest'
// node:test
import test from 'node:test'
import assert from 'node:assert/strict'
```

## 5. 尊重平台自有语义

四条 Windows 判据，本仓库出 Windows 与 macOS 两种包，全部适用：

- **写回值只在断言容忍写回失败时才安全**（mtime 精度、NTFS 的 100 纳秒刻度）。
- **Windows 环境变量名大小写不敏感**——`http_proxy` 与 `HTTP_PROXY` 当作两个键的 fixture，在那里只有一个条目。
- **Windows 异步释放文件句柄**——POSIX 上立即完成的 rename/remove，需要**按实测争用规模定大小的有界重试**。
- **Windows 没有 POSIX 权限与信号语义**——依赖它们的用例**显式平台跳过并写明原因**，而不是到处弱化断言。

macOS 侧目前**没有成文经验**；`build-mac.yml` 与 `ssid-mac-launcher` 相关的问题记录在 `docs/发版流程规范.md` 与 `docs/排查/`。

## 6. 让超时预算对上 lane

三条与运行器无关的判断：

- **用例级超时覆盖运行器默认值**，而不是让位给它——低于 lane 预算的值等于**降低**了已授予的量。
- **提升测试预算时要一起提升钩子预算**——否则只提升 case 预算会把一次争用失败挪进 `afterEach`。
- **被测对象本身是超时时，外层等待要远大于被测超时**——证明 20 ms 截止触发的用例，不能与测试框架自己的等待赛跑。

**默认值是实数字，不是抽象的**：

| 运行器 | 用例级默认 | 钩子级默认 |
|---|---|---|
| vitest 4.1.11 | **5000 ms** | **10000 ms**（写 `0` 完全禁用） |
| node:test | **`Infinity`** | 同（钩子即子测试，各带 `timeout`，未指定则继承父测试） |
| Playwright | 本仓库自设 **60000 ms** | 另有 30 s 导航 / 15 s 动作 |

**vitest 的默认构成 hook : test = 2 : 1 的隐含比例**——把 `testTimeout` 提到 30 s 而不管 `hookTimeout`（仍是 10 s），比例反转成 1 : 3，"争用失败从 case 挪进 `afterEach`"就必然发生。

两个方向的病都要防：

- **vitest 太紧**：默认 5 秒，起进程、等文件系统一类慢用例会间歇撞线，表现得像 flake。
- **node:test 太松**：默认 `Infinity`，**挂住的用例不会失败，只会让 lane 永不结束**——这不是"太紧"，是**缺失失败信号**。

**本仓库的三种态度**：Playwright 已经做对（60 s / 30 s / 15 s 三层递减 + `retries: 0`，是正面样板）；vitest 是裸默认；node:test 无上限。

写法：

| | vitest | node:test |
|---|---|---|
| 用例级 | 第三参数 `it('名字', fn, 30_000)`，或全局 `testTimeout` | 第二参数 `test('名字', { timeout: 30_000 }, fn)` |
| 钩子级 | `hookTimeout`（独立配置项） | **无独立配置项**——钩子就是子测试，各带 `timeout` |

## 7. 用状态同步

- **固定的 sleep 不是 setup 完成或清理结算的证据。**
- 等显式就绪事件、握手、状态转移、自有 promise、可外部观察的条件。
- **超时只用来界定等待，绝不用作让断言成立的条件。**
- 用 deferred promise 或 barrier 把竞态放在确定点，**并证明相关操作确实重叠**。
- **不要断言依赖调度器的顺序**，除非那个顺序就是被测的产品行为。
- 时间本身是主题时，注入或伪造时钟，**并总是恢复真实计时器**。

## 8. 拆除到静默

- **获取后立即注册清理**，这样断言失败也会释放资源。
- 清理顺序：停止新回调/请求 → 摘掉监听器 → 恢复全局钩子 → 终止自有工作 → **等待子进程退出、服务器关闭、worker 终止或等价完成信号**。
- **调用 `abort()`、`close()` 或 `kill()` 而不等待自有的完成信号，是不完整的拆除。**
- 晚完成可能发生时，**证明释放能阻止它变更另一个用例**。

Electron 与 Playwright 测试尤其吃这套：`shell/tests/plugin-adapt/` 的浏览器测试若没等到 `browser.close()` 完成就进入下一个文件，正是这条要抓的。

## 9. 证明预期回归

- 可行时**先观察普通回归在修复前失败**。
- **对新的静态或语料守护，临时引入被拒绝的用例并观察预期失败**（手册 §9 的"先跑红"在这里更具体：**针对守护类检查**）。
- **对竞态用 barrier 证明重叠；重复执行本身不是竞态测试。**
- 对端口、socket、共享路径、子进程，**当跨进程隔离是修复的一部分时要并发跑独立测试进程**。
- **fixture 用自己的截止时间 spawn 时，要先断言没有信号或超时结束了子进程，再去断言退出状态**——否则被杀死的子进程会被报成状态不匹配。
- **验证外部状态、事件、文件、日志、退出或释放，而不是相信组件自报。**
- **压力运行补充确定性回归；它们不替代它。**

## 10. 拒绝掩盖式修复

不要把这些当作确定性本地测试的根因修复：

1. 不指明所等待状态就加大超时
2. 加重试
3. 把所有文件改成串行
4. 吞掉错误或未处理的 rejection
5. 弱化断言
6. 把不稳定行为归一化掉
7. 在清理或断言前加 sleep

**两条区分**：

- 重试对**有文档记载的瞬态外部提供方测试**仍然有效（本仓库对应模型调用类测试）。
- **恢复预算不是掩盖**——把套件提升到它本来就有的 lane 预算，或按**实测的争用**定有界重试，**命名了等待的工作并归还了 lane 已授予的量**。

## 11. 诊断既有 flake

**只做诊断的请求保持只读：报告原因与证据，除非用户同时要求修复。**

诊断路径：本地复现 → Playwright trace（浏览器类）→ 日志定位（`~/.ssid/ssid.log`）→ 对照 `docs/排查/` 的既有记录。

**本仓库的诊断清单尚未建立**：`docs/排查/` 目前只有 1 份记录（窗口不定时跳出）。遇到新的失败模式时，把结论写回那里，**不要凭印象下判断**。

## 12. 验证与报告

按风险加拓扑证据：

| 改了什么 | 要什么证据 |
|---|---|
| 进程全局状态 | 恢复证据（原值是缺失还是存在都验） |
| 生命周期或子进程 | **静默拆除**证据 |
| 端口或共享路径 | **并发独立进程**证据 |
| 新增守护 | **负对照**（无效输入按预期失败） |

跑测试的命令（**每个都核实过存在**）：

| 目标 | 命令 |
|---|---|
| shell 本体（2 个文件） | `npm test` |
| shell 单文件 | `npm run test:profile-merge` / `npm run test:codegraph-adapt` |
| 插件 | `pnpm test`（vitest）或 `npm test`（node:test，看该插件的脚本） |
| Playwright | `cd shell/tests/plugin-adapt && npm test`；另有 `npm run test:ui`、`npm run baseline` |
| dsh-ssid-panels 的两个测试 | `node --import tsx/esm --test plugins/dsh-ssid-panels/tests/release-notes.test.ts`（**必须在仓库根**） |

**两个坑**：

1. **Playwright 不在 `npm test` 里**。shell 的 `test` 脚本只跑那两个 node:test 文件。**只看 `npm test` 绿就宣布"全绿"是错的。**
2. **包管理器不统一**。多数插件只有 `pnpm-lock.yaml`，但 `dsh-memory` 同时存在 `package-lock.json` 与 `pnpm-lock.yaml`——**调用前先看该插件目录里是哪个锁文件**。

报告要说清：改了什么、跑了什么、**有意没跑什么以及为什么**。
