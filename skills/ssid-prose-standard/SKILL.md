# SSiD 行文标准

**写够以保住契约，然后删掉推理记录、重复与装饰。**

**契约**是调用方、被调方、实现者、生产者或消费者所依赖的**义务、不变量、前置条件、后置条件或兼容承诺**。

**REQUIRED BACKGROUND：** `ssid-trim-cot-leakage` 负责**查找与修复**推理痕迹；本 skill 负责判断**每处该保留什么**。两者同批安装。

`contract`、`boundary`、`shape`、`surface`、`seam`、`gate`、`vocabulary` 是**用前要检查的词，不是禁词**——先问"更精确的规则 / API / 字段集 / 类型 / 验证点 / 时序点 / 组件切分 / 失败状态，能不能更好地陈述这个事实"。对照：契约 / 边界 / 表面 / 接缝 / 门禁 / 词汇表。

**注释描述代码表达不了的非显然契约或理由，不复述代码已经蕴含的东西。**

## 输入与排除

**要求显式 `scope`。缺失就报告所需输入并停止**——不要自行推断全仓库范围，也不要开始访谈。

接受 `mode: automatic | interactive`，默认 automatic；只在用户显式要求提问或校准时进入交互模式。**`mode` 控制提问，不控制写入权**：审阅与审计任务报告发现而不编辑；显式要求写入、修复或修剪的任务才应用明确改动。

**始终排除 `vendor/`**（`shell/profile-template/vendor/` 与各插件的 vendor 位），即使是全仓库范围；不要跟随符号链接进入。

同时排除**同步链的冻结副本**：`references/`、与三处 vendor **逐文件全等**的 `plugins/` 副本、`_archived-*` 目录——**改这些地方会破坏同步链**（手册 §10）。

**派生物先改 owner 再重新生成**：`lib/`（由 `src/` + tsdown 生成）与 `shell/profile-template/`（由源同步）。

**变更叙事在本仓库有五个合法主场**：`docs/release-notes-*.md`、`docs/决策/`、`docs/设计/`、`docs/排查/`、`shell/docs/pitfalls.md`——在那里它是**内容本体**，不是泄漏。修剪默认不进入这些路径。

## 保住完整命题

编辑前先识别段落的**每一个命题**，逐个保住：

- actor 与 action；
- 条件、时序与顺序；
- 情态（must / may / never）；
- 否定性保证与例外；
- 归属、副作用、失败模式与后果。

**只在每条事实子句都存活、且结果更清楚时才删形容词、重复与叙事。字数变少本身不是改进。**

三条附属规则：

- 在**使用点保留完整的局部契约**（行为、失败、归属、后果）。
- **一个解释只有一个 home**；架构、理由、算法、历史与扩展示例**激进外链**。
- **非显然理由**在"省掉它可能导致误用或错误简化"时必须保留。

## 按位置规定必需覆盖

**这不是单向缩短**：当代码、类型与结构没有传达下列契约时，要**补写**。

| # | 位置 | 必需覆盖 |
|---:|---|---|
| 1 | **公开 JSDoc** | 调用方可见的返回值区别、抛出或拒绝、副作用、归属、时序、取消、持久性 |
| 2 | **内部注释** | 非局部结构与显然复杂的局部结构：不变量、竞态顺序、归属、安全边界、意外失败行为；**诊断信息**（点名失败的主体或路径、违反的规则、纠正方式）。删除控制流叙述与代码复述 |
| 3 | **模块注释** | 模块的角色、依赖、职责与非显然的架构选择；架构选择链接到属主解释 |
| 4 | **测试** | 只解释非显然的测试设计——为什么需要某个 fixture、断言、平台适配、真实入口路径或间接观测。**删除逐步讲解与清单** |
| 5 | **README** | 消费者契约：配置、语义、失败、限制、扩展点、模型可见影响；含**使用文档**（前置条件、必需操作、真实入口、可观察验证、简明警示）。保留持久缺口与维护者陷阱，不是日常清理清单 |
| 6 | **决策记录** | 独有的理由、机制、备选方案、后果、已交付的验证证据、点名的覆盖空白。已交付的记录用**现在时**陈述现实；删除规划清单，保留钉住决策的证据 |
| 7 | **排查记录** | 事故序列、证据、因果链、影响与预防。删除重复的说服、以及不建立因果的实现细节 |
| 8 | **skill 与 agent 指令** | 行为护栏与**显式 scope 限制**（如"这是指导，不是脚本"）；保持工作流简洁并**链接其权威来源** |
| 9 | **示例与配置注释** | 访问限制、非显然的接线或加载顺序、安全立场、重放行为、例外与可能的误用。不要叙述配置本身已经展示的内容 |
| 10 | **提示词与可见字符串** | **措辞即行为**。文案与无障碍名称、tooltip、placeholder、格式模板**一起看**；改前确认有属主行为证据，没有就保持不变并报告延后 |

**#8 在本仓库尤其要紧**：`skills/` 下有 14 个 skill，本包的每一份也属这一类。

保留可搜索的机制名与有意义的情态、时序或否定强调；只归一化装饰性强调。

## 工作流

1. 确认 scope、mode、当前分支或基线、适用的 `AGENTS.md`。
2. 读 `docs/SSiD开发手册.md` 与属主代码或文档，再判断段落。
3. **检查请求范围，而不只看最大的文件**——用搜索与字数找候选，然后**语义判断**。
4. 把每处候选分类为 **keep / add / trim / restore / restructure / defer**。只在任务授权编辑时应用明确改动；**不要为了满足删除指标而制造编辑**。
5. **先改 owner，再改派生物**；学到新规则后回头复查类似段落。
6. 跑窄范围检查：`npm run typecheck`（shell）或各插件 `pnpm typecheck`，加受影响的 L1 测试；界面字符串改动跑 `verify-zh-ui.cjs`；`git diff --check`。
7. **报告检查范围、明确改动、有意保留、延后项、实际跑过的检查。**

## 边界情形

1. **只有当至少两个版本都满足完整命题规则、且交换的是已接受的原则时，才算边界情形**——一个有唯一保命题答案的改写不是边界情形。
2. automatic 模式下**直接应用明确编辑**，只报告真正的边界情形，**不提问**；**不得为了让进度而弱化命题**。
3. interactive 模式下按治理原则**归组同类段落**，给 2–3 个可行版本、推荐一个、说明事实或结构差异；**不给劣质干扰项**。呈现渠道是**会话内回复**。

## 事实核对：跑，不要假设

**行文陈述的是产品今天的行为，而操作类断言的唯一可采信证据是你真的跑过它。** 每条新文档、以及每一段声称操作、命令、默认值、错误或平台差异的新段落，都适用。

1. **对每条声称的操作，对着当前 checkout 真跑一遍。** 执行文档将展示的每个命令、配置片段、示例的**原样**版本；**只写下你观察到的**，包括确切输出、警告与失败模式。若某断言依赖你没有的密钥或网络，**说明这一点并点名验证属主，而不是断言其行为**。
2. **删掉你无法复现的东西**——**绝不**把命令、字段、默认值或行为从**记忆、类比或邻居包的 README** 搬过来。**当一条断言无法复现时，修那条断言——而不是修测试。**
3. **对着最新代码检查旧文档。** 修订既有文字之前先对照当前源码；**一句陈旧的陈述仍然是错的**——要对着代码改，不是对着旧散文改。
4. **分类主题再写安装指引。** **读事实，不要读文件夹名**：看 `package.json` 的声明与入口文件的形态，而不是目录名暗示的类型。

## 语气规则

1. **开篇说的是主题能做什么。** 开篇 Summary 与用户向小节描述用户或 agent **能用它做什么**——结果、收益、何时选用、主要代价——**绝不是它的角色、类型或内部身份**。"这个插件注册 `ctx.x` 并追加 `x/event` 记录"是身份叙述；"你可以每条消息存一条笔记，重启后还在"才是它做什么。
2. **开发者小节解释，绝不枚举。** 折叠的实现内容覆盖整体设计概念、架构与数据流——**足够了理解它怎么工作**——并**链接代码**取确切细节；**不做完整 API 目录、穷举式字段清单、事件负载枚举或 JSDoc 复述**。
3. **草稿只有一个家。** 半成品想法、草稿、未定方向、实测产物与工作假设**只**出现在末尾并**显式标注非权威**；**其他每一节都是打磨过的当前状态散文**。
4. **只讲当前状态。** 草稿区之外**没有兼容性垫片、迁移话术或历史**（"此前" / "现在" / "不再" / "已改名"）；**今天这个代码库是唯一主题**。
5. **受控的技术语言。** 歧义会改变行为时，让每句话有**显式 actor 与一个主要动作**；一个概念复用一个术语；优先直接动词；拆开堆叠的指令与条件；**保留情态与例外**。
