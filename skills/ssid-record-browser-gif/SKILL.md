# 浏览器录制

产出一段**简短、真实**的界面演示作为本地 GIF。**只有在任务包含把它附到 pull request 时**，才走末尾的发布流程。

优先使用可用的浏览器控制工作流；当该工作流支持更高帧率的连续捕获时用 **Playwright Videos**；用**自带编码器**做裁剪、播放速度、末尾停留、尺寸与体积控制。

**REQUIRED：** 推送前选证据用 `ssid-pre-push-checks`。同批安装。

## 改动用户可见界面就必须录

**改动产品用户可见的界面行为时，必须在同一次改动里更新对应插件的 `docs/shots/`，并确保 README 的 `## 截图` 段引用到位。**

**录制本身就是证据**：用**真实服务器、真实 API key、真实模型回合**。**绝不**用 fixture 查询、mock 传输、合成事件注入或 test-only 钩子替代，除非用户显式要求 fixture 录制。

嵌入处要写明：**被演示的确切 commit SHA、服务它的树与来源、任何模式标志或浏览器状态例外、以及是否跑了真实模型回合**——让评审者知道**这段录像到底证明了什么**。

## 录制与发布分离

- 录制只产出本地视频或截图与一个 `.gif` 产物；**绝不改动远端状态**。
- 发布是**单独的最后一步**，且**只在任务包含附到 PR 时**执行；**绝不改动 PR 自己的分支**。
- **保留所要求的录制条件**：真实服务器或真实 API 的演示**不得**使用 fixture 查询、mock 传输、合成事件注入或 test-only 钩子。**若凭据或服务器不可用，报告这个限制，而不是用 fixture 替代。**
- **绝不读取或暴露凭据值**；走应用的正常配置路径，用一个无害的演示提示。

## 搭建应用

1. 要求干净工作树，用 `git rev-parse HEAD` 记录确切 commit，然后**构建那棵树**：`npm run bundle-kernel`（shell）＋受影响插件的 `pnpm build`。**对着另一个 commit 的构建录出来的 GIF 是错误归因的证据。**
2. 每个端口起一个服务器，用**全新的 `DSH_HOME`、工作区与会话状态**；给浏览器全新隔离上下文。**录制不得碰用户真实 profile**（`~/.dsh/profiles/ssid`）。密钥走应用的正常配置路径；**不要回显它**。
3. **一个分镜就是一次证据运行**：每个已发布帧都来自那个服务器与那些状态根、工作区、会话与模型场景。**若捕获自动化失败，丢弃它的帧并从全新根重跑；绝不把不同运行的帧拼接起来。**
4. 切换任务时，**按 PID 或命令行精确匹配**停掉旧服务器。**宽泛的 `taskkill /IM node.exe` 可能杀掉启动它的那个 shell，包括你自己的。**

## 录制流程

沿用可用浏览器控制工作流的 setup / interaction / cleanup。暴露 `recordVideo` 时，在同一受控上下文启用视频以捕获更多中间帧；**视频可用性不决定该选哪个浏览器控制工作流**。

只有在浏览器控制**不可用**时，才用仓库声明的 Playwright 依赖在隔离无头浏览器里操作，**并在溯源里声明这个退路**。**不要安装另一个驱动，也不要打开用户的浏览器。**

录制前确认来源、构建产物、传输与任何模式覆盖。存脚本、原始视频、计时笔记、QA 帧与 GIF 到被 git 忽略的 `.playwright-mcp/` 下。

**要点**：

- **选择 3–6 个有意义状态的短故事**。行动前等待**唯一语义定位器**；用 `exact: true` 做可及名称等值，以及**无法匹配提示词回显**的精确文本完成判定。**固定等待可以在状态验证后提供阅读停留，但绝不用于确立就绪。**
- 演示工具调用、拒绝或恢复时，**打开它的详情或轨迹**，让视频显示工具身份、状态或稳定错误码、以及下游结果。
- **不捕获任何机密、个人数据、无关标签页或通知**。**浏览器视频包含页面内容而非浏览器外壳**——避免在应用里渲染带凭据的 URL。**审阅整个选定区间，包括中间状态。保持单一视口。**

### 捕获视频

**`viewport` 与 `recordVideo.size` 要显式匹配**，否则 Playwright 会把视频缩到 800×800 以内，**导致界面文字不可读**。

**`context.close()` 要在 `video.saveAs()` 之前 await**——**只关 browser 不保证视频已 flush**。**每个页面有自己的视频**：显式选择被演示的页面，不要拼接不相关的页面或运行。失败的运行只能用于诊断。

## 编码 GIF

需要 `python3`、`ffmpeg` 与 `ffprobe`。**若媒体二进制缺失，报告依赖，而不是未经授权安装软件。**

> **本机当前未安装 `ffmpeg` / `ffprobe`**，所以编码步骤暂时不可用。启用录制能力需要先由用户决定如何提供这两个二进制。
>
> **Windows 上命令是 `python` 而不是 `python3`**：本机的 `python3` 解析到 Windows Store 应用别名（0 字节，执行返回 9009），而 `python` 解析到 `C:\Python312\python.exe`（3.12.1）。**`Get-Command python3` 会报告它存在，但它跑不起来**——下面的命令在 Windows 上把 `python3` 换成 `python`。**存在性检查不等于可用性检查。**

`export GIF_SKILL_DIR=...` **必须单独一行**——**同一命令里的内联赋值无法影响参数展开**。

```sh
export GIF_SKILL_DIR=/absolute/path/to/this/skill
python3 "$GIF_SKILL_DIR/scripts/encode_gif.py" \
  /absolute/path/to/demo.webm \
  /absolute/path/to/demo.gif \
  --start 2 --end 32 --speed 2 --final-hold 3 \
  --fps 10 --max-width 1200 --colors 128
```

`--start` / `--end` 选**一段连续区间**；默认保留整段 1× 速度并加 **2 秒末尾停留**。`--speed` 改变播放速度，**必须在 GIF 旁披露速度与选定区间，免得演示暗示了实测响应延迟**。**用观察到的视频时间，不要猜墙钟偏移。**

**`--fps` 提高不能恢复源录制没有捕获到的运动**。**保留原始 WebM 用于 QA；不要拼接不同运行或合成缺失状态。**

编码器会探测容器时长、在调色板转换前应用裁剪与变速、并检查编码后时长/动画/宽度/字节大小；**它拒绝空区间、越界区间、短于两个输出帧的选择、模式不当的标志与意外覆盖**。

体积过大时**先降 `--max-width`，再降 `--colors` 或 `--fps`；保持文字可读**。**`--force` 只在解决确切输出路径后使用。**

### 截图序列

当连续视频不可用、或用户要求分镜时：**从一次隔离运行里捕获 3–6 个已验证状态**，按 `00-initial.png` / `01-typed.png` 命名；**尺寸与裁剪一致**。瞬态状态要在**同一次浏览器脚本调用内**轮询 DOM 标记后捕获。

```sh
python3 "$GIF_SKILL_DIR/scripts/encode_gif.py" \
  /absolute/path/to/frames /absolute/path/to/demo.gif \
  --durations 1.5,1.5,1.5,3.5 --fps 10 --max-width 1200 --colors 128
```

**一个 duration 适用于每张截图，否则每帧给一个正数，并把稳定状态停留得最久**。**目录输入会拒绝少于两帧、尺寸不一致或 duration 数量不匹配。**

## 验证产物

1. 读编码器的 **JSON 摘要**，核对输出路径、源区间与速度（或截图数）、编码帧数、尺寸、时长与字节大小。
2. **目视阅读编码后的 GIF 本身，而不只是源帧。** 确认过渡可读、最后状态停留足够久、没有敏感内容出现。**若查看器只渲染第一帧，用 `ffmpeg` 从编码后的 GIF 解码代表性帧并检查它们；编码前的截图不能证明编码后的顺序、调色板或末尾停留。**
3. 跑 `git status --short`，**确认原始视频、QA 帧与产物只落在被忽略的路径下**。
4. 返回 GIF 绝对路径，在客户端支持本地媒体时渲染它，**并声明录制用的是真实 API、fixture 还是别的传输**。

**编码器自测**（需要 ffmpeg/ffprobe 已安装，**且不在任何 CI 里跑**）：

```sh
python3 -m unittest discover -s "$GIF_SKILL_DIR/scripts" -p 'test_*.py' -v
```

## 发布

**只在任务包含把它附到 PR 时执行。**

### 主落点：`docs/shots/`

把已验证的 GIF 或 PNG 放进对应插件的 `docs/shots/`，并在 README 的 `## 截图` 段引用（相对路径）。

> **这与"绝不提交二进制"不冲突**：被禁的是把媒体塞进**会被反复合并的分支**以膨胀历史；`docs/shots/` 是 README 的**常驻资产**，本来就该在仓库里。仍然要**控制体积**（`--max-width` → `--colors` / `--fps`）。

### 次落点：上游 PR

`gh --attach` 需要 gh ≥ v2.99.0、github.com、写权限，且 GIF ≤ 10 MB。

- 在 body 里按**普通本地路径引用**；`gh` 会就地重写为上传 URL，**保留位置与 alt 文本**。
- **附上前立即重读被演示 PR 的 live head**，与记录的 commit 比较；**若已移动，停下并重录**。
- 附加后**再次重读 live head 并要求仍停在该 commit**；重读 body 确认引用指向上传 URL；**通过 GitHub Markdown API 渲染 body 确认出现预期 `<img>`**；**抓取上传 URL 一次确认 `200` 与 `image/gif`**。

**退路：assets 分支**（只在 `gh --attach` 不适用时）：孤儿分支，一个 `<series>-assets` 服务整个 PR 系列。

- 推送前**校验该分支只含媒体**，且待推 GIF 的校验和与本地已验证产物一致。
- **永不删除或重写 assets 分支，永不 force-push**——**已合并的 PR body 会永远引用它的 URL**。
- **匿名 404 不能否证私有仓库资产；要认证后再验证。**
