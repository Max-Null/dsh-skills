# 修剪推理痕迹

**推理痕迹**是**视角属于写作会话而不是仓库**的散文：它引用只有那个会话能看到的产物、叙述变更而不是状态、或者与一位已经离场的评审者辩论。

当一段文字承担**事实性子句**时，修法**从来不只是删除**——把每条子句改写成能独立站在当前状态上，再删掉周围的记录。**不承担任何事实**的段落（一个审计编号、一段控制流叙述）直接删除。

**REQUIRED BACKGROUND：** `ssid-prose-standard` 拥有本文引用的**完整命题规则**，它决定"哪条子句必须存活"。两者同批安装——只装本 skill 会让修剪变成删真事实。这是判据，不是脚本。

## 唯一的测试

对每段可疑文字问：

> **一个处在 HEAD、拿不到任何会话记录、PR 讨论或未提交草稿的读者，能不能解析每一个引用、核实每一条断言？**

不能 → 从仓库的视角重述存活的事实，删掉其余。
能 → 它不是泄漏，无论听起来多像历史——**但"可解析"只过了本 skill 这一道闸**：在当前状态表面（README、文档、JSDoc）上，一段**可解析的变更故事仍然是变更叙事**，由第 3 类把它送回合法主场。

## 分类法

1. **死的设计会话引用** —— `(decision 7)`、`(audit C2)`、`设计 §4.7`、`计划 §1.4`、阶段标签（`T4`、`W3`、`P-I`）、"设计台账"、"(B 裁决)"。若该决策有已提交的属主，按名字与路径引用它；否则删掉引用，把它的**事实性子句重述为能独立成立**。
2. **stack 与 PR 视角** —— "本 stack 里后续的 PR"、"本 PR 新增"、"上一个提交"。陈述已交付的机制或扩展点；推迟的工作移入 `TODO` 标记或 issue 引用。
3. **变更叙事与版本戳** —— "此前"、"不再"、"旧版 X"，以及指示性戳记（"v1"、"本版"、"今天"、"现在"与过去状态对照）。陈述**当前行为**；一个已修复的回归变成**现在时的反事实**（"没有 X 时会发生 Y"），而**不是仓库历史**（"以前会 Y"）。
4. **评审编排** —— "评审中被拒绝："、"评审者确认"、草稿序号（"本笔记的 v5"）、轮次归属。保留存活下来的决策与理由作为**平实事实**；删掉**谁在何时说的**。
5. **面向评审者的辩解** —— "这个 cast 是安全的——它只是……"、"这是正确的，因为……"。一段论证自己正确性的注释是对**评审者**说话，不是对维护者。**陈述使代码安全的那条不变量**，或者若代码已经展示它就删掉注释。
6. **复述与推导记录** —— 控制流叙述（"先做 X，再做 Y"）、测试逐步讲解、显然分支的证明。**删除**；只留非显然的契约或不变量。
7. **模糊措辞与规划残留** —— "目前大概没问题"、"应该够了"、没有标记的推迟。提升为 `TODO`/`FIXME` 或重述为**实际的界**；删掉模糊措辞。
8. **写作语言滑落** —— 在语言本已一致的行文里混入未加工的工作语言片段、或未翻译的排版残留（如 `---- 私有 ----` 分隔符）。**翻译或删除**。

## 什么不是泄漏

**无辅助的引用检查会向两个方向出错**：删掉持久引用、留下死引用。下列保留规则**照写执行**：

- **issue 引用** —— `#1470`、`TODO(name):`、"issue #N 负责后续"在 HEAD 处可解析；**任何表面都保留**，包括 README。不要把它们挪进决策记录。
- **决策记录与排查记录里的已合并 PR 与 issue 引用** —— 那是被认可的变更故事证据。
- **抑制理由** —— `oxlint-disable … -- 原因`、覆盖率忽略的理由、空 catch 的解释是**必需行文**；修正一条错误理由，**绝不删除它**。
- **现在时反事实的回归钉** —— "没有 X 时会发生 Y"、"一个朴素的 X 会……"。
- **实测边界** —— "(实测：512 层嵌套 ≈ 0.15 s)"在校准一个常量；**"实测"这个出处词是承重的**。
- **运行时的新旧状态** —— "旧连接在新连接接受之前排空"讲的是**运行时生命周期**，不是变更历史。
- **变更故事段内的历史阶段名** —— "第一版交付了 X"在那里是当前状态安全的；但指示性戳记（"本版"）**在所有地方都禁用**。
- **按设计可解析的仓外引用** —— 标准章节（RFC 9110 §10.1.5）、外部设计稿名；§ 禁令覆盖的是**未提交的内部草稿**，不是外部标准或拥有自己 § 编号的已提交文档。
- **项目口吻与文体形制** —— "我们"作为项目口吻；一份记录的"备选方案"节。
- **变更叙事在本仓库有五个合法主场** —— `docs/release-notes-*.md`、`docs/决策/`、`docs/设计/`、`docs/排查/`、`shell/docs/pitfalls.md`。在这些文件里它是**内容本体**，不是泄漏。修剪**默认不进入**这些路径；确需进入时须由用户显式指定 scope。

## 工作流

1. **定 scope 与豁免**：除 `vendor/` 与同步链的冻结副本外，**默认排除上面五个合法主场**。默认把 scope 收窄到**指令表面**：`skills/*/SKILL.md`、`docs/SSiD开发手册.md`、插件 README、JSDoc 与注释。
2. **先只读审计**：跑[探针](references/recall-batteries.md)（带 `--hidden`），**每条探针先对一个已知正例与一个近失负例校准**，再语义判断每一处命中。**探针是探针，不是定义**——同时无模式地读 scope 内最密的行文（模块 JSDoc、README、skill 正文）。
3. **按表面 owner-first 修**：源侧注释先改，再重新生成派生物（`lib/`、`shell/profile-template/`）；界面字符串改动走 `verify-zh-ui.cjs`。
4. **删任何东西之前先枚举该段的命题**（`ssid-prose-standard` 的完整命题规则），并查[过度修剪陷阱](references/examples.md)——把义务翻转成背书、把假设升格为已交付特性、连带删掉真事实、留下数字丢了出处。**这一步是防过度修剪的唯一闸门。**
5. **验证**：重跑探针，期望只剩合法命中、本 skill 自身的文件与出处引用的证据；确认每条留下的引用在 HEAD 处可解析；改动后**重跑受影响的 L1（typecheck + test）**。

> **本仓库没有文档门禁。** 这一步别处靠 `doc-sync` 一类检查兜底，**这里没有东西替你把关**——验证就是重跑探针加上人对 diff 的判断。不要假设有自动化会接住遗漏。
