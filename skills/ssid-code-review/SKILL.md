# SSiD 代码评审

**这是指导，不是完整清单。** 先确认改动的起点，再读 diff 与**足够理解设计的周边代码**，然后逐项过下面的清单。

**优先正确性、生命周期、安全与必需行为，而不是风格。一条有证据的阻塞项胜过一长串小毛病。**

**REQUIRED：** 本 skill 引用 `ssid-test-reliability` 与 `ssid-prose-standard`。三者同批安装。

## 事实来源

- 工作区根 `AGENTS.md` + `seek-soul-in-darkness/AGENTS.md`：常设的仓库与插件编写规则。
- `docs/SSiD开发手册.md` §9：测试规范与 L1/L2/L3 分级门槛。
- **`ssid-test-reliability`**：拥有资源的、异步的或平台敏感的测试与 fixture 的隔离与回归证明规则。
- **`ssid-prose-standard`**：注释、文档、提示词与可见字符串的必需覆盖与编辑判断。
- `docs/决策/`：设计与理由。**与决策记录意见不同是设计讨论，不是自动否决。**
- **改动的起点**：`git status --short --branch` 与 `git diff --stat <基准>`。**这不是范围报告的等价物——它给路径，不给受影响包与脏层。**

## 阻塞要求

1. **新增行文接受语义评审。** 用 `ssid-prose-standard` 逐段批判性审阅每一处新增或改动的 Markdown、JSDoc、注释、提示词、描述、诊断与可见字符串，对着属主代码或行为核必需覆盖、准确性与位置。**"自己写的文案由自己评"失败率最高——逐段对着属主代码核，而不是重读一遍觉得通顺。**
2. **文档与代码同步。** 配置、默认值、错误、线上字段、事件与公开行为在同一次改动里更新 README 与 JSDoc。注释只陈述非显然契约；把实现叙述、测试逐步讲解、评审历史与重复理由标出来删除，或链到它们唯一的 home。
3. **注册要清理。** 每个新的注册贡献都要有拆除证据——`ctx.effect(...)` 返回的 disposer 被观察到真的撤销了注册。**本仓库的插件大量注册 storage backend、webServer 路由、tools、slots 与 session projections，但测试里目前没有任何 disposal 断言：这是当前缺失的守卫，不是可以略过的一条。**
4. **必需证据存在。** 确认这次改动跑了相关的本地检查（**L1 门槛：typecheck + test 全绿**），并复核门禁检测不到的语义缺口。
5. **界面文案归翻译表。** 拒绝把产品文案嵌进 JSX、模板、helper 返回值、无障碍属性或原语默认值。要求走运行时翻译表（`lib/client.js` 的 `TEXT_ZH`）并跑 `verify-zh-ui.cjs`；**用户、模型与线上数据以及 code token 逐字不动**。

## 手工检查

- **意图与接口契约**：追踪每个改动接口的**两侧**。确认实现与意图一致，包括错误、取消、归属与拆除。
- **生命周期与并发**：对异步 setup、回调、进程或拆除，套用 `ssid-test-reliability`。检查发布前的竞态、await 期间的取消、独立错误上报、回调约束、重入前的归属、完整摘除与静默拆除。
- **能力与消费者匹配**：追踪每一个当前消费者，然后标出泄漏进接口的消费者特有行为。反向也要标：一个泛化服务上的新公开方法**只有一个内部调用方**，是不必要的 API 扩张——要求改为在构造时交给那个消费者的私有能力闭包。
- **范围、归属与必要性**：把每个抽象、状态机、选项、防御性拷贝与兼容路径映射到它的当前契约、生产消费者与属主插件。挑战无关特性与投机性通用化。
- **配置与公开选择**：对每个默认值、公开操作集、格式或引入的外部概念，问它有什么当前消费者证据或先例。证据缺失时要求显式取值或延后。
- **模型视角**：检查模型在各模式下收到的确切提示词、工具 schema、结果与诊断。标出模型任务之外的概念，然后逐字确认稳定文本、用端到端覆盖确认动态行为。
- **强制点**：沿每条拒绝路径追到**真正执行它的那个操作**；用能绕过 schema、提示词、门面、包装或监听器顺序的直接与替代调用方来试。
- **借用与派生状态**：判断每个保留值在包契约下是**借用**还是**拥有**，然后把通知与每个缓存、提示词、界面回声、重放与查询视图追到已记录的提交点与权威来源。
- **边界覆盖最终操作**：定位完整产物或保留结果的属主，包含包装与元数据。用极小与精确的界限、超大单块与多字节文本试探字节上限。
- **真实入口路径**：测试要走**交付形态**的入口——Electron 壳（`main.mjs`）→ `kernel.bundle.mjs` → profile 装载，以及插件的 `package.json` 导出面（`main` / `exports` / `dsh.client`）。**手工 import 抓不到 `cordis.patch.yml` 与 exports 面的错误。**
- **测试强度**：断言要在预期回归上失败，并验证**外部状态、日志、事件或拆除**，而不是复述实现或相信 agent 的自报。覆盖率是必要的，但不是"场景正确"的证据。**一条蓄意无效的用例必须经由真实运行器按预期规则失败**（负向控制）。
- **测试可靠性**：对拥有资源的、异步的、平台敏感的或已经不稳的测试，套用 `ssid-test-reliability`——真实 worker 拓扑、资源分配、全局状态恢复、同步、超时预算与静默拆除。
- **决策记录与已交付现实一致**：确保决策记录里陈述的机制、路径与名字**与实际交付一致**；不一致时**改记录或改代码，不留着两说**。
- **截图基线的变化**：`shell/tests/plugin-adapt/baselines/` 的基线变了要问**为什么变**。**把基线的 diff 当作行为变更来评审，不是格式噪音**——不要重新生成就完事。

**审阅新增或修改的文档与 skill 正文时，再逐条过这六问**：

| # | 判据 | 要问的问题 |
|---:|---|---|
| 1 | **Brief** | 常用路径只含其结局所需的事实；穷尽真相保持在一个直接链接或一层细节之外 |
| 2 | **Intuitive** | 前置先于依赖概念；下一步动作是显然的；标题用读者会搜的词 |
| 3 | **Friendly** | 读者能识别成功、行动前理解风险、从可能的失败中恢复、并选择是否继续深入 |
| 4 | **Accurate** | 每条持久断言有一个属主，以及与其风险相称的验证路径 |
| 5 | **Agent-readable** | 元数据、稳定标题、锚点、术语、归属、状态**支持定向检索，而不必加载整个语料** |
| 6 | **Newcomer-complete** | 一个没有仓库上下文的专业工程师，能通过 3–5 个链接页重建相关架构或特性 |

## 报告发现

陈述**缺陷、位置、影响与证据**四要素。

**交付前自审**：报告进会话内的交付说明，按**阻塞项 / 建议**分开。**已被 L1 门禁守住的事不重复报告。**

**上游 PR**：缺陷挂最紧的相关 diff 行内，跨切面用 PR 级评论，用既有 review thread 回复。

**收到评审时**：**逐条核实，以技术理由修正或反驳，不做表演性同意。**
